# Catopia technical decisions

## Initial decisions

### Application framework

Use Next.js App Router, React and strict TypeScript as the initial application foundation, matching the supplied product specification and execution prompts. Introduce Three.js/React Three Fiber and MapLibre only with the world/map stages so the foundation stays lean.

### Backend boundary

Use Supabase PostgreSQL/Auth/Storage as the planned source of truth. Keep browser-safe Supabase configuration separate from server-only privileged configuration. A local shell without credentials must report that the backend is not configured rather than displaying fabricated persisted data.

### Data and location safety

Use UUIDs for internal records and stable human-readable Cat IDs for public display. Keep geographic coordinates separate from 3D presentation coordinates. Publish landmark or approximate sighting locations by default; precise sensitive animal locations must not be public.

### Identity and moderation

Treat new cat identity as provisional until reviewed. Do not merge cats automatically based on photo similarity. Public counts and feeds should only include records allowed by moderation policy. Enforce permissions in server/database rules, not only in the interface.

### Asset handling

No assets were present in the workspace during the audit. Do not treat listed marketplaces or packs as acquired assets. Record source, author, license, attribution, file path and compatibility before production use. Verify each pack's actual license; availability for free download does not establish production rights.

### Architecture sequence

Establish a runnable application and configuration baseline first, then design/navigation, shared location/world data, 3D world and map, cat/community workflows, server-side gamification, integration and release hardening. This resolves the differing phase groupings in the source prompts while preserving their dependency order.

## Conflicts and resolution

- **Animation libraries:** One section mentions GSAP and React Spring; no feature requires either at foundation time. Avoid adding both by default and choose only when a concrete interaction needs them.
- **Demo data vs. no fake production data:** Prompt examples permit demonstration locations, while the product rules prohibit fabricated production records. Any future seed/demo fixtures must be explicitly labeled and isolated from production paths.
- **Asset checklist vs. missing supplied assets:** Asset acquisition is a goal, but no assets or verified source files were in the repository. Catalog only assets actually acquired and inspected.
- **Test tooling:** The prompts recommend Vitest and Playwright. Add them when application behavior exists and the toolchain is available; do not claim checks that could not run.

## Community product decisions (approved for prototype direction)

- Start with DYPIU Akurdi, Pune, and nearby areas; Catopia should remain usable for other localities later.
- Support sightings, portraits, and memories.
- Contributor identity is private by default, with an explicit public opt-in and a gentle anonymity recommendation.
- Master admin can create sub-admins and assign role-scoped access. Production permissions and audit requirements still need implementation design.
- Map direction is a street map with filters and paw markers; public cat locations remain broad and reviewed.
- The Phase 2 prototype may use supplied reference images only when clearly labeled as samples/portrait studies.
- Add a dedicated Plays browse section for community cat videos. Preserve each uploaded clip's original aspect ratio; do not crop every clip to a portrait-only format. Until approved video samples and uploads exist, the prototype uses clearly labeled still-image layout samples.
- Use the existing MapLibre dependency with OpenFreeMap vector styles for the map preview; retain provider attribution. Do not create sample cat pins or sightings. Keep the map empty of animal records until reviewed data and permissioned storage are available. Street-level imagery requires a separately reviewed provider and token.
- Map place-discovery (cat cafés, shelters, adoption centres, vets, pet shops, grooming, cat-friendly spots) is a separate concept from cat sightings/pins above and is not subject to the "keep empty" rule, since these are ordinary public businesses, not animal records: query real business data from the public Overpass API (OpenStreetMap) by category tag (`amenity=veterinary`, `shop=pet`, `shop=pet_grooming`, `amenity=animal_shelter`), and fill categories OSM has no usable tag/data for (cat cafés, general cat-friendly spots) with a handful of names/descriptions that say "sample"/"concept" outright. Never attach a rating, review count, or photo to a place unless it came from a real source (OSM tag) or Catopia's own session-local review system — no fabricated review data, ever. Ratings/reviews/saved places are session-only `useState` (no Supabase project is configured), matching the same non-persistence convention used by Saved stories and PAW. Directions open an external Google Maps link (no routing API key configured) rather than drawing an in-app route.
- The Stories nav section was replaced with a concept Store (food, treats, litter, toys, grooming, health, furniture, carriers) per explicit direction, since Stories' filterable-list layout was already duplicated by Discover/Home. Every product is an original Catopia-concept name — never a real brand, never real inventory — since there is no real supplier relationship to represent honestly. No payment form or payment provider is used anywhere in the checkout flow (not even a fake one): checkout only collects a name/address/phone and ends with an explicit "nothing was charged or delivered" confirmation. Cart/order state is session-only `useState`, matching every other non-persistent feature, since no Supabase or payment provider is configured.
- Store detail pages use a `?product=<id>` query value within the existing `/community-preview` shell. Next.js's documented native History API integration keeps the in-page selection refreshable and browser-back aware without introducing a second storefront routing shell. The current catalog contains no product image, rating, review, variant, specification, supplier, stock-count, shipping-policy, or delivery data, so the detail view uses a clearly-labeled original category illustration and omission/empty states rather than presenting those fields as real. Cart and wishlist remain session-only preview interactions.
- Store redesign (boutique catalogue + left filter drawer): the 8-category placeholder taxonomy was replaced with a 10-category/subcategory concept taxonomy (`store-data.ts`), each product optionally carrying `lifeStage`/`material`/`size`/`color` so the filter drawer's facets (Life Stage, Material, Size, Colour) are computed live from `PRODUCTS` and scoped to the active category/subcategory — a facet section is only rendered when at least one matching product has that attribute, so no empty or irrelevant filter option is ever shown. The old right-aligned dropdown filter panel was replaced with a true left-sliding drawer (`role="dialog"`, body scroll-locked while open, closes on Escape/overlay click/explicit close button, ~300ms easing, sticky "Show N products" footer) per explicit design direction, plus a "Shop by Category" discovery-tile grid above the toolbar and a removable active-filter chip row above the product grid. No rating, review-count, discount, or stock-count values are fabricated anywhere in the catalogue or filters — "New"/"Staff pick" are the only product tags, both editorial rather than statistical, and there is deliberately no Rating filter or Brand filter since no real review data or multi-brand catalogue exists yet. "Newest Arrivals" sort is based on catalogue array order (last-added = newest), not a real timestamp, since no creation-date field exists; this is a known simplification, not fabricated metadata.
- Store product page: the gallery is driven by `getProductGallery(product)` (`store-gallery.ts`). Real photographs supplied through the optional `Product.images` field are used as-is; otherwise a labelled sample set is built from crops of the user-supplied toolkit photos, mapped only to products whose item genuinely appears in a photo, and products without a match show a concept plate. Every product also gets a typographic details slide built from its real attributes, so nothing in the gallery implies product facts that the catalogue does not hold. The page shows no rating, review count, discount or stock number. Colour and size selectors appear only when a product has that data; the size choice is local to the page and is not stored in the bag (stated on the page) because the session cart carries no variant. The store page's product boxes (category rows and grid tiles) were deliberately left as they were; the page-level change is limited to the page that opens when a box is clicked, and its related row reuses the same box.
- Map 3D Earth mode: built on the existing MapLibre dependency with no new packages. Buildings are extruded from OpenFreeMap's OpenStreetMap `building` layer (heights from `render_height`; features without a height fall back to a default of 6 m so none render black, which is a visual default, not a data claim). Elevation comes from AWS Terrain Tiles (Terrarium encoding) with a hillshade layer; sky, light and globe projection use MapLibre's own style features. Satellite imagery reuses the Esri World Imagery source that was already in the Satellite theme. 3D layers are added only while the mode is on and are removed when it ends; `setStyle` is called with `diff: false` so themes rebuild deterministically. The camera is limited to 80° tilt and 2D keeps a 0° tilt limit and the local minimum zoom. The default map theme became Catopia's Cozy theme. The map UI now lives in `map-screen.tsx` (moved out of `preview.tsx`) and uses vendored React Bits components (Counter, Magnet, ShinyText, StarBorder, ClickSpark, GradualBlur, GlareHover). Place sample and review behaviour is unchanged and still session-only.
- Standalone game direction (planning only, no game code yet): the controller icon in the top bar will replace the profile "P" and open a standalone cozy exploration game (its own route; no 3D/2D toggle; the map stays in Community). Look: HD-2D, meaning low-poly 3D scenery with pixelation, outlines, tilt-shift, bloom, warm lights and particles, plus pixel-art cat sprites at the same pixel density; the player is a cat; camera presets change by location (tilted fixed view for the street, isometric for interiors) and are stored in each map's data. First area: an invented market street (a labelled placeholder, not the real campus). Loop: cozy exploration with light quests and collectibles, no combat, timers or fail states. Art route: open/CC0 assets plus procedurally generated art; no external AI generation services. A one-to-two-day look test comes before committing to the pipeline. Installed on 2026-11-25 for this: five game/pixel-art skills (see `INSTALLED_SKILLS.md`), `postprocessing` and `@react-three/postprocessing`, and the Kenney Fantasy Town Kit. Cats in the game stay clearly-labelled sample/original characters, locations stay invented or approximate, and cat interaction stays observe-only.
- Phase 0 look test (approved by the owner on 2026-11-25; evidence, measurements and the round-1 and round-2 history in `LOOK_TEST.md`): look B, an HD world with a pixel-art cat (HD-2D). Pixel-art textures at about one cat-pixel per texel are projected onto the stock pieces; windows are lit panes with light spill; the cat is a 48 px normal-mapped lit sprite with a sprite-shaped shadow; the miniature blur is a custom bokeh depth-of-field with an asymmetric sharp band that follows the cat, with foreground framing objects in the bottom corners; grain is off and posterize is rejected; quality tiers are Full, Light and Minimal and change render resolution and anti-aliasing; the camera is perspective at FOV 28 degrees, pitch 34 degrees, distance 14. The standard postprocessing tilt-shift was unsuitable and is replaced by a custom effect. Frame-time and load targets stay "to confirm in Phase 1", because look B at Full is over the 60 fps budget on an integrated GPU and no phone has been measured. The lab is throwaway, dev-only and returns 404 in production.

- Game Phase 1: shell and render foundation (built and verified 2026-11-25; evidence in `docs/phase1/`). **Structure:** the game lives in `features/game/` (`capability`, `quality`, `settings`, `shell`, `audio`, `render`, `world`, `debug`) and the route in `app/play/`. The rules (shell state machine, quality tiers and governor, pixel grid, settings validation, audio bus, batching and geometry builders, camera pose, frame statistics) are plain TypeScript with Vitest tests (`npm test`, node environment, 212 tests); React components only draw and report clicks. **Entry:** the top-bar "P" avatar became a link to `/play` with a controller icon, `prefetch={false}` and the label "Play the Catopia game world". The profile stays in the sidebar ("Your contributions"). The avatar had been hidden on the Map and PAW screens and below 760px; the controller is visible everywhere because it is an entry point. **Route and loading:** `app/play/page.tsx` (server: metadata and a `viewportFit: cover` viewport) renders a client loader that imports the shell with `next/dynamic` and `ssr: false` (Next.js allows that only in a client component), so Community pages carry none of the game: their scripts grew by 0.6 KB gzipped for the icon and link. **Assets:** the 72 Kenney pieces are packed by `scripts/build-town-pieces.mjs` into one binary file, a manifest and one shared colour map (five game files in all; about 145 requests before). Their UVs keep glTF's convention, so the colour map is loaded with `flipY = false`. **Rendering:** static pieces are merged by surface key (pixel pattern plus tint) after their transforms are baked in, giving 7 meshes; code-built props merge into 2 (wood and plain, colour in the vertices); window panes batch into 3 atlas meshes, plus one mesh of soft halos and one of light pools, with the flicker computed on the GPU from a per-window phase shared by a window, its halo and its pool; lamp halos are one instanced mesh of billboards. Draw calls fell from about 510 to 56 (counted over every pass) and the Full tier from about 20 to about 7 ms per frame. The surface shader projects each pixel texture along the surface's dominant axis (one fetch instead of three). Bunting keeps the look test's raw (unconverted) vertex colours because that pastel look is what was approved. Khronos Neutral tone mapping is applied by the post stack and, at the Minimal tier, by the renderer itself, so the tiers look alike. Shadows use `"percentage"` because three 0.187 removed the soft type and warns when it is requested. **Quality:** tiers are as decided in Phase 0. A governor steps down after two 90-frame windows averaging over 22 ms, steps up only on trial (after 20 s of comfortable windows, judged over two windows, and a failed trial is blocked for the session), makes at most 8 changes, ignores frames over 250 ms (a throttled or returning tab) and the first four frames. The first guess comes from device hints (touch with 6 or more cores and 4 GB or more starts at Light, other touch devices at Minimal, desktops with 4 or more cores at Full); the player can pin a tier. **Cat size:** the cat's picture covers about 11.5% of the window height (`CAT_SCREEN_FRACTION` in `world/stage-constants.ts`), in a whole number of drawing-buffer pixels per sprite pixel measured at the cat's own depth from the camera (not the distance to the point the camera aims at), so its pixels stay even. The sprite quad, its contact shadow and the blur's sharp band all follow that size. Phase 0 had the picture at 16 to 20% of the height, which you judged too big in the running game on 2026-11-25, so it was cut by about a third (whole-pixel scaling makes the result 10 to 14% depending on the window's height). The world's texture detail was left alone, so the cat's pixels are now finer than the cobbles' (about 2 against about 3.4 screen pixels at 1600x900). **Window light:** changed on 2026-11-25 after you pointed at it. The version carried over from the look test was a wide, flat, pale box under every window and a hard-edged patch on the cobbles, both bright enough that the tone mapping turned them into plateaus with no gradient left in them. Each window now has a soft elliptical halo that reaches zero brightness before its edge, and the cobbles in front of ground-floor windows get a pool of light that starts about as wide as the window, widens and blurs as it travels away from the wall, fades out, and carries faint shadows of the window bars. The shapes are plain functions (`render/window-light-shapes.ts`) whose tests check that no edge is hard; the strengths are `HALO_GAIN` (0.38) and `POOL_GAIN` (0.8) in `world/window-lights.tsx`. **Shell:** a state machine (checking, unsupported, loading, ready, playing, paused, lost, error) decides the screen. The only control on screen while playing is a small II in the far top-right corner (a 26 px symbol with a 48 px touch area); leave and sound moved into the pause menu. Pausing freezes the game: it uses `frameloop="demand"`, so nothing animates but the picture still redraws after a resize or a setting change and is never blank; a hidden tab pauses itself; Escape pauses and resumes; M turns sound on and off. **Pause menu** (`shell/pause-menu.tsx`, with its rules in `pause-menu-model.ts` under test): the frozen picture is darkened, blurred (CSS `backdrop-filter`) and drained of a little colour, and the choices float over it as plain text rows: Resume, Sound, Picture quality, Motion, Performance numbers, Leave the street. Up and down (or Tab) move the highlight and wrap round, Home and End jump, left and right flip a switch or step a choice, Enter or Space presses a row, Escape resumes; pointer and touch work too (moving highlights, a click presses or steps forward). The highlight is drawn as colour, a sweeping underline and a paw that glides between rows; opening staggers the rows in and a changed value slides in from the side it moved; Reduced motion switches all of that off. Key repeats of Escape and M are ignored (holding Escape used to flicker the menu open and shut), and the game's root box uses `overflow: clip` rather than `hidden`: a hidden box can still be scrolled by a focus or a script, and the wide performance readout once slid the whole menu sideways that way, so the box now cannot scroll at all and the readout is capped to the screen width and wraps. The highlighted row is kept in a ref, so a burst or held key can never skip a row or step backwards (a synchronous burst of key events did, before). Rows are `menuitem` and `menuitemcheckbox`, keyboard focus follows the highlight and changes are announced in a live region. On a narrow phone the arrow hints beside values are hidden so the longest row stays on one line. Narrow portrait screens (under 700px wide and taller than wide) get a "turn your phone sideways" hint with "Play anyway". With no WebGL 2 the player sees a friendly screen and nothing is downloaded; in development `/play?webgl=off` shows it. **Sound:** the audio context is created and resumed inside the Begin click; mute sets the master gain to zero and is remembered; pausing the game ducks and muffles the game's own sound but keeps the audio context running, because the pause menu makes its own sounds, and a hidden tab suspends the context; a mute waits 0.22 s so the sound that announces it is heard while an unmute is immediate; the game's own sound is its background music (see Background music below). **Menu sounds** (`audio/ui-sounds.ts`, generated with the Web Audio API, no files): short, soft, electronic and tactile, following the brief of muted digital clicks, delicate synth blips, subtle airy textures, tiny mechanical ticks and smooth tonal transitions, with a very short reverb and nothing harsh, loud or like a mouse click. They are made of tiny band-passed-noise ticks, soft low pulses, rounded sine and triangle notes (a gentle pentatonic ladder as the highlight moves down; two notes rising or falling when a value changes or a switch flips; a rising pair for pressing; a falling pair for leaving), airy filtered-noise sweeps (down when the menu opens, up when it closes) and a generated 0.28 s reverb, mixed 6 dB above their recipes (`UI_LEVEL`). Each sound is a small data recipe tested against the brief (every sound ends within 0.3 s, notes only sine or triangle with a highest partial under 2.3 kHz, ticks under 15 ms, no layer above 0.16 gain), and holding a key cannot turn them into a buzz because repeats of one sound are spaced 45 to 100 ms apart. Measured offline at the default volume (`docs/phase1/ui-sounds-report-2026-11-25.json`): peaks 14.5 to 19.4 dB below full scale, audible for 47 to 183 ms, spectral centre 554 to 1559 Hz, none clipped. They were measured, not listened to, by whoever built them. **Background music** (`audio/music.ts`): on 2026-11-26 the opening piece (6:03) of a recording the owner supplied, "Beyond the Vale", replaced the generated breeze. It is streamed from `public/audio/background-score-1-beyond-the-vale.mp3` by an `<audio>` element joined to the game's sound path (`createMediaElementSource`), not decoded into memory, so it costs 5.8 MB of transfer and almost no memory, and it starts on the Begin click rather than on the loading screen. It loops with the element's own `loop`, because the piece begins in silence and ends in a fade to inaudible. It goes through the same world filter and world gain as the breeze did, so pausing the game ducks it by about 10 dB (measured 10.2 dB) and muffles it (subtly: the music is already soft and low), the Sound switch silences it while it keeps running, a hidden tab pauses it and the tab coming back plays it again, and leaving the game stops its download. Its level is one constant (`level` 0.45): the output measures about −30 dBFS RMS at the default volume. The recording is 3 h 12 min and 176 MB, too big for the web and for git (GitHub rejects files over 100 MB), so only a lossless 6:03 cut made by `scripts/cut-game-music.mjs` is served and committed; the original stays in the git-ignored `assets/source-audio/`. Its licence is unverified, so it is prototype-only (`ASSET_LICENSES.md`). **Settings:** `localStorage` key `catopia.game.settings.v1` (mute, quality, motion, performance readout), validated on read, written only when the player changes something, and the game still works when storage is blocked. **Reduced motion** (the Motion setting, or the device's preference when set to follow it) turns off window and lamp flicker, halo shimmer, bunting and sign sway, fireflies drifting, falling leaves and the cat's idle loop; the camera is fixed in Phase 1. **Verification hooks:** `window.__catopia` (`perf`, `bench`, `fingerprint`, `audio`, `feedFrame`) exists in development, and in production only with `/play?perf=1` or the performance readout switched on; it lets frame cost, graphics-context counts, pixel fingerprints, audio state and the governor be checked without trusting screenshots.

- Website scroll bars and the landing page's way into the community (2026-11-26; checks and measurements in `docs/PROJECT_STATUS.md`). **No visible scroll bars anywhere on the site**, as a deliberate look decision. One global rule in `styles/catopia.css` sets `scrollbar-width: none` on `html` and, because that property is not inherited, on every element, plus `::-webkit-scrollbar { display: none; width: 0; height: 0 }` for older WebKit. Every declaration is `!important`, so a later component rule cannot bring a bar back by accident (a new scroll area needs nothing added; only a later `!important` rule could undo this). The rule is scoped to `html:not(.cg-locked)`, so `/play`, which locks page scroll itself and sets `cg-locked` on `html` while it is mounted, is left exactly as it was, including the native bar on the game's overflow card. Nine older per-container hide rules (`preview.css`, `consistency.css`, `map.css`, `place-panel.css`, `paw.css`, `store.css`, `product-gallery.css`) are now redundant but harmless and were left in place. Three declarations that contradicted the rule were removed: `scrollbar-width: thin` with `scrollbar-color` on `.cp-stories-rail` and `.cp-reel-scroll`, and `scrollbar-gutter: stable` on the Plays reel. **Trade-off:** with no bar there is no visual cue of how long a page or panel is or where you are in it; scrolling itself (wheel, touch, keyboard) is unchanged, and the only hints left are controls and layout that suggest more (the Plays and Store arrow buttons, a stories rail that runs past the edge). **Side effect:** Discover's content is `calc(100vw - 76px)` wide and `100vw` includes a classic bar, so Discover used to scroll 15 px sideways on desktop; with no bar it no longer overflows. **Landing page to community:** the header pill ("Community preview") and the hero's main button ("Visit the community preview") link to `/community-preview` through `next/link`, the way `preview.tsx` links home. The button carries a one-line note, "A design preview with sample stories — nothing is saved yet.", tied to it with `aria-describedby`, so the promise matches the "Catopia is not open yet" close and the Community page's own "sample portraits are not real Catopia profiles". They replace the old pill ("Come be part of it", an anchor to the close) and the old main button ("Take a look around", an anchor to the concept guide) instead of adding to them, because the header is already squeezed between 761 and 860 px (measured link widths of 57, 68 and 135 px at 761 px against a natural 75, 89 and 165) and a fourth item would not fit; both old targets stay reachable from "Why Catopia", "The little world" and the in-page links, and the hero keeps "Why we made this". Prefetching is left at its default: `/community-preview` is a dynamic route with no `loading.js`, and in the production build the landing page made only small prefetch requests for it and loaded none of the preview or map scripts. `/` initial JavaScript is 184.0 KB gzipped (180.8 KB was recorded on 2026-11-25; the only code change on `/` is `next/link`, so the 3.2 KB is most likely its client code; no before-and-after build was made to isolate it) and `/community-preview` is unchanged at 301.5 KB.
