- **Map crash fix (2026-11-26).** Cause: the 3D-exit handler in `InteractiveMap` (`map.once("moveend", …)`) called `remove3dLayers` and `setProjection({ type: "mercator" })` with no regard for a style that was still loading. MapLibre delivers `moveend` synchronously when another camera move (a `flyTo` after choosing a place, or a zoom button) interrupts the ease, so `Style is not done loading` was thrown inside a React effect and replaced the whole page. In development, React Strict Mode also re-ran the mode effect on mount, whose old "first run" flag let that second run start a flat-map ease on its own. Changes: the mode effect now reacts only to a real change of `mode3d` (`appliedMode3dRef`, reset for each new map); the 3D enter/leave style edits go through `tryStyleWork`, which logs a warning instead of throwing, because `applyOverlays` rebuilds the right layers when the style does load; the camera commands moved to `runCommand` and run inside a `try/catch`; and `MapErrorBoundary` (`app/community-preview/map-error-boundary.tsx`, wrapped around `MapScreen` in `preview.tsx`) turns any remaining map failure into a quiet "The map hit a problem" panel with "Try again" while the sidebar, top bar and other screens stay up. The fallback-style work already in the tree (local style first, retry button) is unchanged.
  - **Checked** (in-app browser, dev server, 375 px pane, with `window.fetch` patched in the page to hang or reject requests to OpenFreeMap, Esri, AWS terrain and Photon): *Reproduced first* by temporarily restoring the old behaviour: with the Positron style pending (requests hanging), toggling 3D on, off, then pressing Zoom in threw `Style is not done loading`, and only the new error boundary kept the sidebar up (the console showed "Catopia map crashed and was contained by its error boundary"). *With the fix*, the same sequence only logs the warning "could not leave 3D yet", no uncaught error, no boundary, sidebar up. ## Current blockers and assumptions

- Public campus-specific content cannot be built accurately until the campus/locality is identified and reference data is supplied or independently verified.
- A live Supabase integration cannot be verified until a project URL and public anon key are configured; privileged keys must remain server-only.
- The Map's place-discovery feature has no routing/directions API key configured, so "Directions" opens an external Google Maps link rather than drawing an in-app route. Reviews and saved places are session-only (no backend) by the same constraint; see `docs/TECHNICAL_DECISIONS.md` for the full data-source and persistence notes.
- The default Turbopack build hits a Windows worker startup failure in this environment. The `build` script uses Webpack, which completed a production build successfully.
- The project will use Next.js, React and TypeScript as the documented baseline, while optional technologies such as MapLibre and React Three Fiber are introduced only when their stages begin.
- Fixed on 2026-11-26 (was: the Map crashed the whole page while its remote style or tiles were timing out; see the Map crash fix entry under "Completed in this session"). Remaining limit: MapLibre errors thrown from its own timers or animation frames, outside React effects, are still not caught by the error boundary (none was seen).
