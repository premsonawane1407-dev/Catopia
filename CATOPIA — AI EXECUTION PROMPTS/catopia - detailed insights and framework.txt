# CATOPIA
## Product Requirements, Technical Architecture & Codex Implementation Specification

Version 1.0  
Project type Interactive community platform + exploration game  
Geographic scope Campus + surrounding locality  
Visual direction Cozy indie game, stylized 3D, illustrated maps, artistic UI  
Development approach AI-assisted development using OpenAI Codex

---

# 1. PRODUCT VISION

Catopia is a community-powered digital world dedicated to the real cats living around a university campus and its surrounding neighbourhood.

Users should be able to

- Discover cats living around their campus and locality.
- Upload photographs of cats they encounter.
- Record where and when they spotted a cat.
- Give unidentified cats names through community voting.
- Create permanent identities for individual cats.
- Explore an interactive virtual representation of the campus.
- View cat profiles, personalities, stories and sighting histories.
- Participate in community activities and earn achievements.

Catopia should feel like a small, living indie game rather than a conventional social networking website.

## Core product philosophy

1. Every cat deserves an identity.
2. Every sighting contributes to a cat's story.
3. Every user can contribute to the community.
4. The virtual environment should reflect real-world locations.
5. The experience should be delightful even when users are simply exploring.

## 1.1 Primary objectives

- Build a beautiful and functional interactive world.
- Make cat discovery intuitive and enjoyable.
- Establish reliable cat identities and prevent duplicate records.
- Make community contributions easy.
- Connect virtual locations to actual geographical locations.
- Ensure the application works on desktop and mobile.
- Maintain a scalable architecture for additional campuses and localities.

## 1.2 Non-goals for the first release

Do not attempt to build

- A complete open-world multiplayer game.
- Real-time multiplayer character movement.
- Complex combat or RPG mechanics.
- AI-powered facial recognition as the sole method of identifying cats.
- A massive photorealistic city simulation.
- A complicated social networking system.
- Native Android or iOS applications.

These features may be considered in future versions.

# 4. INTERACTIVE WORLD ARCHITECTURE

This is the most visually important part of Catopia.

## 4.1 Hybrid exploration system

Implement two connected representations of the same geographical world.

Representation 1 Interactive 3D world

A stylized, explorable environment with
- Buildings.
- Trees.
- Roads.
- Gardens.
- Walkways.
- Animated cats.
- Clickable landmarks.

Representation 2 Illustrated 2D map

A stylized map showing
- Real-world landmarks.
- Cat sighting locations.
- Cat population hotspots.
- User-submitted sightings.
- Areas of interest.

Switching between these views must preserve the selected location whenever possible.

## 4.2 Camera system

Desktop
- Third-person or free exploration camera.
- Orbit and pan controls.
- Zoom controls.
- Smooth transitions.
- Click-to-focus on locations.

Mobile
- Touch-based camera controls.
- Pinch-to-zoom.
- Tap-to-select.
- Simplified movement controls.

Do not make first-person movement mandatory.

## 4.3 World interaction

When users click a building
- Highlight the selected building.
- Display its name.
- Show cats associated with that area.
- Display recent sightings.
- Provide an option to view the corresponding real-world map location.

When users click a cat
- Display a small floating nameplate.
- Show its photograph or avatar.
- Provide a View Profile action.
- Highlight its associated real-world location.

When users hover over a cat
- The cat may look toward the cursor.
- Display its name.
- Show a subtle outline or visual highlight.

## 4.4 World data model

Do not hardcode every building and cat inside the 3D scene.

Create a data-driven world system.

Every landmark must have
- Unique landmark ID.
- Name.
- Description.
- Geographic coordinates, if available.
- 3D world position.
- Associated map position.
- Associated cats.
- Visibility status.

Every cat must have
- Cat ID.
- Current profile data.
- Associated sightings.
- Virtual world position.
- Location association.
- Display model or sprite.

The 3D environment should retrieve these records from the backend.

## 4.5 Performance requirements

- Use instancing for repeated environmental objects.
- Use low-poly or optimized models.
- Compress textures.
- Implement level-of-detail where appropriate.
- Lazy-load environment assets.
- Avoid loading the entire environment before rendering the interface.
- Provide a lower-quality graphics mode.
- Provide a 2D fallback for unsupported devices.

Target smooth performance on ordinary modern laptops and mid-range mobile devices. Treat 60 FPS as a desktop optimization target, not a guaranteed minimum.

# 5. CAT IDENTITY SYSTEM

Every cat must have a permanent unique identity.

Example

CAT-0001 — Mochi  
CAT-0002 — Simba  
CAT-0003 — Unknown Cat

## 5.1 Cat profile

Each profile should contain

- Unique Cat ID.
- Community-approved name.
- Alternative names or previous names.
- Main photograph.
- Additional photographs.
- Description.
- Personality tags.
- Physical identification features.
- First discovered date.
- Last sighted date.
- Frequently visited locations.
- Total verified sightings.
- Community stories.
- Naming history.
- Verification status.

## 5.2 Unidentified cats

New sightings should not automatically create a permanent cat identity.

Instead

1. User submits a photograph.
2. User provides location and description.
3. The platform searches for potentially matching existing cats.
4. User can select an existing cat.
5. User can flag a possible match for moderator review.
6. If no match exists, a provisional cat record can be created.
7. The record receives a permanent Cat ID once accepted.

## 5.3 Duplicate prevention

Implement a manual-first identification process.

Use
- Similarity in photographs as an optional suggestion.
- Physical descriptions.
- Location proximity.
- Sighting history.
- Community reports.
- Moderator review.

Do not automatically merge two cats based only on image similarity.

## 5.4 Community naming

Unidentified cats should have a naming process.

Workflow
1. An unidentified cat receives a temporary name such as Mystery Cat #12.
2. Community members submit name suggestions.
3. Users vote on suggested names.
4. Voting remains open for a configurable period.
5. Moderators can approve the winning name.
6. The selected name becomes the official community name.

Maintain a record of previous names and naming decisions.

# 6. SIGHTING SYSTEM

The sighting system is the primary source of new content.

## 6.1 Create a sighting

Users should be able to

- Upload one or more photographs.
- Select an existing cat or propose a new cat.
- Select the location.
- Add a caption.
- Add the date and approximate time.
- Add optional behaviour tags.
- Submit the sighting.

Example

Spotted this little orange fellow sleeping outside the library again. He seems to own the place.

Location Library Garden  
Date 20 November 2026  
Cat Mochi

## 6.2 Sighting feed

Create a visually engaging feed featuring
- Latest sightings.
- Recently discovered cats.
- Popular cats.
- Nearby areas.
- Community contributions.

Each sighting should connect to the cat profile and location.

## 6.3 Sighting verification

Possible statuses
- Pending.
- Approved.
- Rejected.
- Flagged.

A sighting should not increase verified statistics until approved or otherwise accepted under the moderation rules.

## 6.4 Location accuracy

Do not expose precise feeding spots, nests or sensitive animal locations publicly by default.

Use approximate map locations or designated public landmarks.

Allow moderators to access more precise information when operationally necessary.

# 11. SECURITY AND MODERATION

Security must be implemented from the beginning.

Requirements

- Secure authentication.
- Server-side authorization.
- Row Level Security.
- Validated image uploads.
- File size restrictions.
- MIME-type validation.
- Rate limiting.
- Spam prevention.
- Report functionality.
- Moderation queue.
- Audit logs for administrative actions.
- Secure environment variables.
- No service-role key in browser code.

Protect users' personal information.

Do not publish precise private user locations.

For cat sightings, show public landmarks or approximate coordinates by default.

Never expose sensitive animal locations, such as vulnerable nesting areas, publicly.

The platform must not encourage users to chase, feed, handle or disturb cats.

# 12. ASSET ACQUISITION STRATEGY

Do not spend weeks creating every 3D asset from scratch.

Reuse properly licensed assets.

Potential sources

1. Kenney — stylized environment and game assets.
2. Poly Pizza — low-poly 3D assets.
3. Sketchfab — 3D models with suitable licenses.
4. itch.io — indie game asset packs.
5. Mixamo — compatible character animations.
6. Blender — custom models and adjustments.
7. Rive — interactive UI animations.

For each asset, maintain a record of
- Asset name.
- Original source.
- Creator.
- License.
- Attribution requirements.
- Local file path.

Do not assume that an asset is free for commercial use just because it can be downloaded for free.

## 12.1 Asset priorities

Essential
- Cat models or sprites.
- Cat animations.
- Trees.
- Grass.
- Buildings.
- Benches.
- Paths.
- Flowers.
- Lighting assets.
- UI icons.
- Environmental sounds.

Optional
- Birds.
- Butterflies.
- Decorative particles.
- Ambient music.
- Weather effects.

## 12.2 Art consistency

Do not mix
- Photorealistic buildings.
- Cartoon cats.
- Low-poly trees.
- Completely unrelated illustration styles.

Choose a consistent asset family and adjust materials, lighting and scale to create a coherent world.

- More sophisticated 3D character behaviour.
- Multiplayer exploration.
- Cat activity timelines.
- PWA installation.
- Advanced map-based discovery.

Any AI-assisted matching must be treated as a suggestion system, not definitive proof of identity.

# 17. DEFINITION OF A SUCCESSFUL MVP

Catopia MVP is complete when

1. Users can access the platform.
2. The homepage is visually polished.
3. Users can explore a working interactive world.
4. Cats are represented by animated characters.
5. Every cat has a permanent identity.
6. Users can browse cat profiles.
7. Users can upload sightings.
8. Sightings can be associated with existing cats.
9. Unidentified cats can be named through the community.
10. Real-world locations connect to virtual landmarks.
11. Gamification works correctly.
12. Moderators can manage submissions.
13. Mobile users can use the essential features.
14. Critical security and automated tests pass.

A visually impressive demo that cannot save or retrieve real data is NOT an MVP.

# 18. DEVELOPMENT RULES FOR CODEX

Codex must follow these rules throughout the project.

1. Inspect the existing repository before making changes.
2. Never replace working code without understanding its dependencies.
3. Build features in small, testable increments.
4. Do not generate the entire application in a single step.
5. Never hardcode application data that belongs in the database.
6. Use TypeScript strictly.
7. Keep frontend and backend responsibilities separate.
8. Validate all user-submitted information.
9. Enforce permissions server-side.
10. Create migrations for database changes.
11. Test every major feature before moving forward.
12. Do not silently ignore errors.
13. Never leave non-functional placeholder interactions.
14. Document asset licenses.
15. Preserve existing functionality when implementing new features.
16. Keep the application responsive.
17. Optimize the 3D experience rather than sacrificing performance for visual effects.
18. Record architectural decisions in documentation.

If something cannot be implemented reliably, Codex must explain the limitation and propose a smaller working alternative.

# 19. FINAL PRODUCT EXPERIENCE

The finished experience should feel like entering a cozy, living digital neighbourhood.

A visitor opens Catopia.

They see a beautifully illustrated world.

A little orange cat is walking near the library.

They click it.

A profile opens.

They discover that the cat is called Mochi, that people have spotted it 34 times, and that it likes sleeping near the garden.

They notice another unidentified cat.

They upload a photograph from their phone, add a caption and select the location.

The community suggests names.

People vote.

The cat gets its identity.

The next time someone opens Catopia, that cat is part of the world.

The real world creates the stories. Catopia brings those stories to life.
