This is the next thing I'd prepare before development.

Part 4. Create custom skills specifically for Catopia
This is something I particularly recommend.

Generic skills teach Codex how to build software. Custom skills teach it how to build your particular project consistently.

Create these three additional skills inside your Catopia repository.
Custom skill 01
catopia-art-direction

Keeps the entire website visually consistent.

Responsibilities:
- Enforce the cozy indie visual identity.
- Maintain colour and typography rules.
- Prevent generic SaaS-style components.
- Keep 2D and 3D assets visually coherent.
- Guide illustrations and animations.


Custom skill 02
catopia-3d-world-builder

Specialized instructions for building the actual world.

Responsibilities:
- Load and optimize GLB models.
- Manage animated cat characters.
- Build interactive landmarks.
- Manage camera and scene interactions.
- Implement fallback rendering.
- Optimize scene performance.


Custom skill 03
catopia-asset-manager

Prevents Codex from randomly importing assets.

Responsibilities:
- Inspect downloaded assets.
- Check formats and compatibility.
- Maintain license records.
- Optimize textures and models.
- Maintain consistent scale.
- Avoid duplicate or unnecessary assets.


Custom skill installation prompt
Give Codex this instruction:
Create three project-specific Codex agent skills inside .agents/skills/.

Create:
1. catopia-art-direction
2. catopia-3d-world-builder
3. catopia-asset-manager
Each skill must contain a valid SKILL.md with YAML frontmatter containing name and description.

For catopia-art-direction:
- Follow Catopia's cozy indie game visual identity.
- Use warm cream, sage green, muted forest green and terracotta.
- Maintain consistent typography, illustrations, components and animation.
- Avoid generic SaaS designs and repetitive card layouts.
- Preserve visual consistency across desktop and mobile.
For catopia-3d-world-builder:
- Follow React Three Fiber and Three.js best practices.
- Use optimized GLB assets.
- Implement reusable animated cat components.
- Support camera controls, clickable landmarks and cat interactions.
- Optimize rendering, texture sizes and scene complexity.
- Support reduced motion and low-performance devices.
For catopia-asset-manager:
- Maintain a centralized asset registry.
- Track asset source, author, license and attribution requirements.
- Check model formats and texture dependencies.
- Ensure models have consistent scale and orientation.
- Prefer GLB for web delivery.
- Optimize images and textures.
- Avoid duplicate assets and unlicensed downloads.
- Never replace a high-quality approved asset with an arbitrary placeholder.
Each skill must contain practical instructions, examples, applicable workflows and clear activation descriptions.

Make these skills specific to Catopia rather than generic programming guides.

Do not modify application functionality while creating them.

Part 6. Tell Codex how to use the downloaded assets
Once you've downloaded some packs and placed them in the directories, give Codex this prompt.
I have added a collection of visual and 3D assets to the Catopia repository.

Your task is to inspect and organize these assets before implementing the environment.

Use the catopia-asset-manager skill.

For every asset:
1. Identify its file format.
2. Identify its dimensions and approximate size.
3. Inspect its visual appearance.
4. Determine whether it is suitable for the Catopia art direction.
5. Check whether required textures and animation files are present.
6. Record its source and licensing information.
7. Identify duplicate or unnecessary files.
For 3D models:
- Prefer optimized GLB files for web delivery.
- Inspect geometry and texture complexity.
- Verify orientation and scale.
- Check animation clips.
- Identify missing materials.
- Check whether the model is suitable for React Three Fiber.
Create:
- ASSET_CATALOG.md
- ASSET_LICENSES.md
- ASSET_COMPATIBILITY_REPORT.md
Do not blindly import every asset.

Select a coherent collection that works together visually.

Do not use assets with unknown licensing in the public application until their permissions have been verified.

Recommend which assets should be optimized, converted, replaced or retained.

Do not modify the existing application yet.

First produce the complete asset audit.




Part 7. Important additional instructions for Codex
I would also create a project-level AGENTS.md file in the repository root.

This gives Codex persistent project instructions, while skills provide specialized workflows.
CATOPIA — AGENTS.md
Project identity
Catopia is a cozy, artistic, interactive community world dedicated to real cats living around a campus and its surrounding locality.
Design principles
- Never create a generic SaaS-looking interface.
- Maintain the cozy indie game aesthetic.
- Prioritize visual quality and functional interactions.
- Maintain consistent colours, materials, lighting and typography.
- Keep the 2D map and 3D world visually connected.
Asset principles
- Inspect available assets before creating new ones.
- Reuse properly licensed assets.
- Prefer GLB for optimized 3D web assets.
- Maintain an asset license register.
- Never use unknown-license assets in production.
- Do not use random unrelated models.
- Avoid unnecessary large downloads.
Engineering principles
- Use TypeScript.
- Follow modular architecture.
- Keep business logic out of visual components.
- Use Supabase as the source of truth.
- Never hardcode production cat or sighting data.
- Validate inputs on the server.
- Enforce authorization and RLS.
- Use database migrations.
- Add automated tests.
3D world principles
- Optimize models and textures.
- Use lazy loading.
- Implement graceful loading states.
- Avoid blocking the main interface.
- Support mobile devices.
- Respect reduced-motion preferences.
- Never sacrifice core functionality for visual effects.
Development workflow
Before implementing a major feature:
1. Inspect the relevant code.
2. Read relevant agent skills.
3. Create an implementation plan.
4. Identify dependencies.
5. Implement incrementally.
6. Run tests.
7. Inspect the actual browser output.
8. Fix defects before declaring completion.
Never claim that a feature works without verifying it.

One last thing: Don't make Catopia look like a collection of free assets
The difference between an average project and a beautiful indie-game experience is often not the number of assets.

It's how they are combined.

For Catopia, I would aim for:
- One consistent art style.
- A carefully designed campus environment.
- Cats with distinct personalities and animations.
- Beautiful UI that feels like part of the game.
- Real photographs integrated into stylized cat profiles.
- Subtle ambient sound and environmental motion.
And I'd make the actual campus recognizable through your own photographs and landmark references.

My ideal outcome: Someone opens Catopia, sees a tiny animated cat wandering around a beautifully recreated version of their campus, clicks it, and discovers that it's a real cat they have probably walked past hundreds of times. 🐈

That's the experience worth building.
